# Verification Model

## 適用範囲

各文書では検証手順を定めていますが、いずれにおいても検証をいつ開始するのか、結果がいつまで有効か、結果をどう提示するかを定めていません。

本文書では次を定めます。

- 検証がどの段階で構成されるか
- 各段階の入力が何であり、その同一性をどう扱うか
- 検証結果が何を含み、どの状態を取りうるか
- 結果がいつまで有効であり、いつ再利用してよいか
- 結果を提示するときにどのような制約をおくべきか

本文書は特定の配信媒体に依存しません。HTML文書における具体的な検証処理は、次の文書が定めます。

- Site Profile Verification Processing in HTML Documents
- Content Attestation Set and Originator Profile Set in HTML Documents

### 本文書で扱う検証の意味的範囲

OPB における検証は、次のすべてを含みます。

- 署名の検証 (検証鍵による署名済みデータの完全性の確認)
- 条件の充足確認 (allowedURL の照合など)
- コンテンツの完全性の確認 (Content Integrity Descriptor の照合など)

:::note

Architectural Overview (以下 AOV) は Verify を署名による完全性の確認に限定し、Validate を実態や信頼できる情報源を参照した真正性の評価として定義しています。OPB の「検証」はこれらより広い意味をもちます。AOV は日本語において Verify と Validate がいずれも「検証」と訳されうることを用語課題として挙げており、将来の文書統合時に整合が図られる予定です。本文書は OPB の既存の用法にしたがい、検証の意味的範囲を上記の通り明示します。

:::

## 適合対象

本文書の要件は、明示のない限り検証者に課されます。提示の要件は、検証結果を利用者に提示する検証者に課されます。すべての検証者が結果を提示するとは限りません。例えば、コマンドラインの検証ツールや配信経路での検証器は結果を提示しないため、提示の要件の対象外です。

利用者には、本文書のいかなる要件も課されません。

## 検証段階

検証は、次の5つの段階で構成されます。

1. 探索 Discovery: 検証対象を見つける
2. 解決 Resolution: 検証に必要な材料を用意する
3. 検証 Verification: 対象と材料に対して、検証を適用する
4. 保持 Retention: 検証結果を保ち、有効性を追跡する
5. 提示 Presentation: 検証結果を利用者に提示する

段階は依存関係を持ちますが、対象ごとに独立して進行します。1つの対象が検証の段階にあるとき、別の対象が探索の段階にあってもかまいません (MAY)。

## 検証入力

検証入力 (Verification Input): 検証に用いる材料の総体。対象そのものと、解決の段階で揃えた材料を含みます。

### 入力の同一性

検証入力は可変になりえます。対象が時間とともに変化する場合、検証はある時点の状態に対しておこなわれます。

入力スナップショット (Input Snapshot): 可変な検証入力の、ある時点における状態

1つの検証結果の検証入力は、単一の入力スナップショットでなければなりません (MUST)。複数の時点にまたがる入力から、1つの結果を導いてはなりません (MUST NOT)。

入力同一性 (Input Identitiy): ある2つの検証入力が同一とみなせるかの判定。

検証者は、入力同一性を判定する手段を保持しなければなりません (MUST)。検証入力そのものを保持することは要求されません。

### 入力の範囲

入力範囲 (Input Scope): 検証に用いてよい材料の範囲。

検証者は、入力範囲の外にある材料を検証に用いてはなりません (MUST NOT)。具体的な範囲は、それぞれの検証処理モデル文書が定めます。

入力範囲は、検証結果に記録されなければなりません (MUST)。同じ対象であっても、利用する材料が異なれば結果の意味が異なるためです。

### 入力の由来

同一の成果物であっても、取得経路によって扱いが異なり得ます。ある経路で得た材料が、別の経路で得た材料と同等に扱えるとは限りません。

検証処理モデル文書は、その扱う成果物の取得経路を明示し、経路ごとに入力範囲と入力同一性の判定方法を定めなければなりません (MUST)。

## 検証結果

検証結果 (Verification Outcome): 検証の出力。

### 結果の範囲

検証結果は、少なくとも次を含めなければなりません (MUST)。

- 検証対象の識別
- 検証範囲
- 入力範囲
- 結果状態
- 入力同一性の判定手段

検証入力そのものを含むことは要求されません (NOT REQUIRED)。

### 結果状態

結果状態 (Outcome State): 検証結果がとりうる状態。

結果状態は、次のいずれかをとります。

- 未検証: 検証を開始していない
- 検証中: 検証を開始したが結果が確定していない
- 検証済み: すべての検証を通過した
- 検証失敗: いずれかの検証を通過しなかった
- 失効: いったん確定した結果が、検証入力の変化によって現在の検証対象に対して有効でなくなった

:::note

これらの名称は仕様の記述のためのものであって、利用者に提示する表現ではありません。

:::

### 状態遷移

- 未検証から検証中への遷移は、検証の開始を契機とする
- 検証中から検証済みまたは検証失敗への遷移は、すべての検証の完了を契機とする
- 検証済みから失効への遷移は、6.2 節の条件を契機とする
- 検証失敗から検証済みへの直接の遷移は存在しない (MUST NOT)。検証を通過しなかった対象について再び検証を行う場合、それは新たな検証結果である
- 失効から他の状態への遷移は存在しない。失効した結果について再び検証を行う場合、それは新たな検証結果である

### 検証範囲

検証範囲 (Verification Scope): 検証結果が、対象の何について示しているか。

検証対象の全体について検証をおこなった場合と、その一部について検証をおこなった場合では、結果の意味は異なります。検証者は、両者を区別できる形で検証範囲を記録しなければなりません (MUST)。検証範囲が検証対象の全体でない場合、検証済みは対象の全体が検証を通過したことを意味しません。

## 結果の寿命

有効性 (Effectiveness): 検証結果が、ある時点で成り立っていること。

:::note

Verifiable Credential の有効期間 (Validity Period) とは別の概念です。VC の有効期間は検証対象であって、本セクションの有効性は検証結果の性質を表します。

:::

### 失効

失効: 検証範囲は変わらないまま有効性を失った状態。

失効は検証失敗ではありません。失効は現在の対象について確認できないのであって、検証失敗が示すところの検証を通過しなかったことを意味しません。両者を同一に扱ってはなりません (MUST NOT)。

検証結果は、その検証入力が変化した時点で失効します (MUST)。何を検証入力の変化とみなすかは、それぞれの検証処理モデル文書が定めます。

### 再利用

再利用可能性 (Reusability): ある検証結果を、別の文脈において再び用いてよいこと。

検証者は、次の両方が満たされる場合に限り、検証結果を再利用してかまいません (MAY)。

- 検証範囲が同一であること
- 入力同一性が保たれていること

いずれかが満たされない場合、再利用してはなりません (MUST NOT)。具体的な同一性の判定方法は検証処理モデル文書が定めます。

## 提示

本セクションの要件は、検証結果を利用者に提示する検証者に課せられます。

- 未検証および検証中の状態を、検証済みとして提示してはなりません (MUST NOT)
- 検証済みから失効への遷移は、提示に反映しなければなりません (MUST)
- 失効を検証失敗と同一の表現で提示してはなりません (SHOULD NOT)
- 検証範囲が対象の全体でない場合、どの範囲について検証がおこなわれたかを利用者が識別できる形で提示しなければなりません (MUST)
