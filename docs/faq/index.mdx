# よくある質問

## OP 対応について

### OP 対応するには WordPress またはそれをベースとした CMS を使う必要がありますか

いいえ。  
WordPress のプラグインはあくまでも参照実装であり、各社で実際にご利用の CMS に OP 対応を行うことができます。

### コンテンツの OP 対応するには CMS の内部実装に大きく手を入れることが必須でしょうか

いいえ。  
WordPress プラグインのように、CMS 内部の処理で CA を生成・登録する形が望ましいですが、CMS 内部の実装に手を入れるのが難しい場合、CA サーバーや [OPVC CLI](/opvc-cli/) を使用して CA を生成することができます。

### 複数のサイトを運用しているのですが、どのサイトで実装するのが良いでしょうか

自社コンテンツを掲載するサイトであればいずれでも構いません。  
単純な構成のサイトの方が対応は簡単ですが、実装上の課題を見つけるという目的としては、より複雑な仕組みのサイトでお試し頂く方が良いかもしれません。本ドキュメントをご覧になって可能な範囲で対応いただくことをご検討ください。

### CA サーバーの API を使ったところ、 400 Bad Request のエラーが返ってきました。どのような原因が考えられますか

CA サーバーの使い方については、[API ドキュメント](https://reference.originator-profile.org/api/)をご確認ください。  
発生したエラーに関しては、[エラーリファレンス](/error-reference/)にて情報を参照することができます。それでも解決しない場合はお問い合わせください。

## OP/CA の使い方・運用について

### OP ID とは何ですか。コンテンツを出版するサイトのドメイン名と OP ID は一致させたほうがよいですか

OP ID は法人などの組織に対して割り振られる ID です。  
ID の形式として、その組織の情報を示す主たるサイトのドメインを採用しています。コンテンツを出版するサイトのドメイン名と OP ID は異なるもので構いません。1 組織が複数のメディアサイトを運営する場合や、メディアサイトとは別に企業ページがある場合には、一致させないほうが良いでしょう。  
詳しく知りたい場合は [OP ID のドキュメント](/opb/op-id/) を参照してください。

### 利用者の課金状態などに応じて表示が変わるコンテンツにはどのように CA を発行すべきですか

課金・無課金でのコンテンツそれぞれに対して CA を発行してください。

### 複数ページにわたるコンテンツにはどのように CA を発行すべきですか

各ページに 1 つずつ CA を発行してください。

### コンテンツを更新した際には、必ず CA の再発行が必要ですか

更新内容によります。  
更新により CA に記載した情報が古くなった場合には CA の更新を実施（再発行）してください。

### コンテンツを更新し、それに合わせて CA も再発行したいです。出版物の ID（CA の `credentialSubject.id`）は更新前後で同じ値にしたほうがいいですか

同じ値にしてください。  
コンテンツと CA の `credentialSubject.id` は一対一対応するため、異なる値を指定した場合、元の出版物とは異なる CA として発行されます。同じ値にすることで CA は更新されます。

### 記事を非公開・削除しました。 CA も削除すべきでしょうか

削除したほうがよいでしょう。  
CA の中にはタイトルや著者などの記事の情報が含まれているため、記事削除・非公開後に CA にアクセスできる場合、それらの情報がユーザーに見えてしまいます。

### 記事を非公開状態で新規作成しました。 CA は発行すべきですか

CA は記事の公開と同時に発行され、記事閲覧ユーザーからアクセスできることが期待されます。  
非公開状態での新規作成の場合は CA は発行しなくても構いません。

### CA に履歴の概念はありますか

CA のデータには更新履歴やバージョンについての情報はありません。  
ユーザーには最新の CA の情報だけが提示されます。
