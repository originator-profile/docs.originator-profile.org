## OP Inspector

検証中の警告と情報を詳細情報画面で確認できるようになりました。また、Profile Annotation Issuer 登録証 PA の検証方法を見直しました。

### Added

- 詳細情報画面に、検証中に発生した警告 (Warnings) と情報 (Info) を表示するようにしました。
  非推奨の `Certificate` モデルの使用や、`digestSRI` の欠落と不一致などを、ブラウザーのコンソールを開かずに確認できます。
- Content Attestation はあるものの Site Profile がないサイトで、「サイトプロファイルが見つかりませんでした」と表示するようにしました。
- External Resource Target の `cssSelector` プロパティに対応しました。→ [ドキュメント](https://docs.originator-profile.org/ja/opb/content-integrity-descriptor/external-resource/)
  `cssSelector` があれば、HTML 要素に `integrity` 属性を付けなくても対象要素を特定できます。

v0.6:

```json
{
  "type": "ExternalResourceTargetIntegrity",
  "integrity": "sha256-OYP9B9EPFBi1vs0dUqOhSbHmtP+ZSTsUv2/OjSzWK0w="
}
```

```html
<img
  src="https://example.com/image.jpg"
  integrity="sha256-OYP9B9EPFBi1vs0dUqOhSbHmtP+ZSTsUv2/OjSzWK0w="
/>
```

v0.7:

```json
{
  "type": "ExternalResourceTargetIntegrity",
  "cssSelector": "#hero-image",
  "integrity": "sha256-OYP9B9EPFBi1vs0dUqOhSbHmtP+ZSTsUv2/OjSzWK0w="
}
```

```html
<img src="https://example.com/image.jpg" id="hero-image" />
```

### Changed

- Profile Annotation Issuer 登録証 PA の検証で、OP レジストリ (トラストアンカー) が発行した登録証 PA を認可チェックから免除する例外規定を撤廃しました。→ [ドキュメント](https://docs.originator-profile.org/ja/opb/pa-model/profile-annotation-issuer-registration/)
- PA 発行者の認可を確認できない場合は、警告ではなく情報として通知するようにしました。
  認可を確認できないことは、PA が無効であることを意味しないためです。
- Site Profile がないサイトで表示する文言を「このサイトはまだOPに対応していません」に変更しました。
- リンク先確認 (広告リンクの遷移先が、コンテンツの表明した運営者のサイトかを確認する機能) で、リンク先の OP の署名も検証するようにしました。
- アイコンを iconify API 経由で取得せず、拡張機能に同梱するようにしました。
- Site Profile に含まれる Website Profile の一部をデコードできない場合も、残りの Website Profile を検証するようにしました。
  エラーメッセージには、デコードできなかった Website Profile の位置 (`sites[1]` など) を示します。

### Deprecated

- `VisibleTextTargetIntegrity` を非推奨としました。
  `innerText` によるレンダリング結果はブラウザー間で一致しないため、完全性の検証には使えません。
  この Target Integrity を含む Content Attestation を検証すると警告を表示します。
  `TextTargetIntegrity` (あるいは `HtmlTargetIntegrity`) に移行してください。→ [ドキュメント](https://docs.originator-profile.org/ja/opb/content-integrity-descriptor/text/)

v0.6:

```json
{
  "type": "VisibleTextTargetIntegrity",
  "cssSelector": "#main",
  "integrity": "sha256-GYC9PqfIw0qWahU6OlReQfuurCI5VLJplslVdF7M95U="
}
```

v0.7:

```json
{
  "type": "TextTargetIntegrity",
  "cssSelector": "#main",
  "integrity": "sha256-GtNUUolQVlwIkQU9JknWkwkhfdiVmHr/BOnLFFHC5jI="
}
```

`integrity` の値は再計算が必要です。

### Removed

- ビルド時に同梱した認証情報を使って、レジストリ API に Basic 認証でアクセスする機能を削除しました。
  これに伴い、拡張機能が要求する権限から `webRequest` と `webRequestAuthProvider` を削除しました。

### Fixed

- Chrome ウェブストアのようにコンテンツスクリプトを注入できないページで、非サポート画面と詳細情報からエラーの理由が消えていた不具合を修正しました。
- リンク先確認の Warning 画面と詳細情報に、誤った組織名が表示される不具合を修正しました。
- リンク先確認の Warning 画面で「このままアクセスする」を選んでも、しばらく操作していなかった場合に再び警告が表示される不具合を修正しました。
- オーバーレイの CSS の誤記 (`outilne`) を修正しました。

## WordPress プラグイン

### Added

- CA Manager に、指定した URL パターンに一致する記事を CA の自動発行から除外する設定を追加しました。
  たとえば `/blog/**` を設定すると、`/blog/` 配下の記事を公開または更新しても CA を発行しません。
  設定は次回の公開または更新から適用され、発行済みの CA は削除も失効もしません。
- 画像の integrity 値を取得できず署名に失敗した場合に、ログを出力するようにしました。
- 管理画面で `VisibleTextTargetIntegrity` が非推奨であることを表示するようにしました。
- 公開済みの記事に CA を一括で発行する画面を「ツール > CA一括発行」に追加しました。
  投稿タイプ、公開日、カテゴリで対象を絞り込み、「未発行のみ」か「全件」を選んで発行できます。
  処理は 1 記事ずつ進み、一時停止、再開、キャンセルと、失敗した記事の再試行に対応します。
  URL パターンによる除外設定も適用します。
- 画像の External Resource Target に `cssSelector` を含めるようにしました。
  WordPress が画像ブロックの `<img>` 要素に付ける `wp-image-{添付 ID}` クラスから、`img.wp-image-123` のようなセレクターを求めます。
  以前に署名した CA を検証できるように、`<img>` 要素への `integrity` 属性の付与は続けます。

### Changed

- CA サーバーのホスト名の初期値を `playground.originator-profile.org` に変更しました。
- サポート対象の PHP をアクティブなセキュリティサポートがあるものとする方針を README に明記しました。

### Fixed

- WordPress 7.x でパーマリンク設定が「基本」のとき、API 認証 (OIDC) 画面が 404 エラーになる不具合を修正しました。
  OIDC リダイレクト URL の変更は、CA サーバーの次期リリースで対応する予定です。

## npm パッケージ

### Added

- CA サーバーで Content Attestation に署名するためのクライアントライブラリ [`@originator-profile/ca-client`](https://www.npmjs.com/package/@originator-profile/ca-client) を追加しました。
  - `createCaClient`：未署名 CA への署名 (`sign`) と既存 CAS の再署名 (`reSign`) を CA サーバーに依頼するクライアントを生成します。
  - `writeCasFile` / `readCasFile`：Content Attestation Set ファイルを読み書きします。
  - `detectDrift`：ビルド後の HTML から Target Integrity を再計算し、CAS に記録された値とのずれを検出します。
- `@originator-profile/verify`：サイトを対象とする `verifyWebsite` と文書を対象とする `verifyDocuments` を追加しました。
  OP Inspector と同じ一連の検証処理を、他のアプリケーションから利用できます。
- `@originator-profile/verify`：VC Data Model 2.0 の検証結果に倣った、シリアライズ可能な検証結果の型を追加しました。
  エラーは [エラーリファレンス](https://docs.originator-profile.org/ja/error-reference/) の URL を `type` に持つ Problem Details として、所在を示す `pointer` とともに記録します。
  警告と情報は `warnings` / `info` に記録します。
- `@originator-profile/verify`：検証中の警告と情報の出力先を、`logger` オプション (`{ warn, info }`、デフォルトは `console`) で差し替えられるようにしました。
- `@originator-profile/presentation` / `@originator-profile/verify`：VC の取得結果と、OPS および CAS の検証結果に、取得経路 (`source`) を含めるようにしました。
  取得経路は、レジストリ、Site Profile、HTML への埋め込みのいずれかです。
- `@originator-profile/sign`：`signJwtVc` / `signWsp` / `signCp` / `signCa` の鍵引数で `CryptoKey` / `KeyObject` と、外部の署名者を表す `JwtSigner` を受け付けるようにしました。
  HSM やクラウド KMS など、秘密鍵を取り出せない環境で署名できます。
- `@originator-profile/model`：External Resource Target に `cssSelector` プロパティを追加しました。
- `@originator-profile/model`：`UnsignedContentAttestation` の `credentialSubject.id` を省略可能にしました。
  省略すると CA サーバーが CA ID を採番します。

### Changed

- **破壊的変更** `@originator-profile/verify`：`verifyImageDigestSri` / `OpsVerifier` / `SpVerifier` の末尾の省略可能な引数 (`fetcher` / `validator` / `verifyOrigin`) を、オプションオブジェクトにまとめました。

v0.6:

```ts
await verifyImageDigestSri(image, fetcher);

OpsVerifier(ops, keys, issuer, validator);

SpVerifier(sp, keys, issuer, origin, verifyOrigin, validator);
```

v0.7:

```ts
await verifyImageDigestSri(image, { fetcher });

OpsVerifier(ops, keys, issuer, { validator });

SpVerifier(sp, keys, issuer, origin, { verifyOrigin, validator });
```

- `@originator-profile/verify`：`SpVerifier` は、Website Profile の一部をデコードできない場合も残りを検証し、すべての Website Profile の検証結果を元の順序のまま `SiteProfileInvalid` に含めて返すようにしました。

### Deprecated

- `@originator-profile/model`：`VisibleTextTargetIntegrity` を非推奨としました。

### Removed

- **破壊的変更** `@originator-profile/opvc`：`signByServer` を削除しました。
  代わりに `@originator-profile/ca-client` の `createCaClient` を使用してください。
  認証はアクセストークンから OAuth client credentials (`ccspConfig`) に変わります。
  `issuedAt` / `expiredAt` は指定できず、署名時刻から 1 年間有効な CA となります。

v0.6:

```ts
import { ContentAttestation } from "@originator-profile/opvc";

const jwt = await ContentAttestation.signByServer(uca, {
  endpoint: "https://example.com/ca",
  accessToken: process.env.CA_SERVER_ACCESS_TOKEN!,
});
```

v0.7:

```ts
import { createCaClient } from "@originator-profile/ca-client";

const client = createCaClient({
  endpoint: "https://example.com/ca",
  issuer: "dns:example.com",
  ccspConfig: process.env.CA_SERVER_CCSP_CONFIG!,
});
const jwt = await client.sign(uca);
```
