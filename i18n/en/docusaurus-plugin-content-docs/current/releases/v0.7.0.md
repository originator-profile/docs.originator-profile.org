# v0.7.0

## Release Information

- **Version**: 0.7.0
- **Release Date**: Oct 6, 2026
- **GitHub**: https://github.com/originator-profile/originator-profile/releases/tag/v0.7.0

---

## OP Inspector

You can now view warnings and information related to validation on the details screen. Additionally, the validation method for the Profile Annotation Issuer Registration PA has been revised.

### Added

- Warnings and Info that occurred during verification are now displayed on the detailed information screen.
  You can check for things like the use of deprecated `Certificate` models or missing and mismatched `digestSRI` without opening the browser console.
- "Site profile not found" is now displayed for sites that have Content Attestation but no Site Profile.
- Added support for the `cssSelector` property of External Resource Target. → [Documentation](https://docs.originator-profile.org/en/opb/content-integrity-descriptor/external-resource/)
  With `cssSelector`, you can identify the target element without adding the `integrity` attribute to the HTML element.

v0.6:

```json
{
  "type": "ExternalResourceTargetIntegrity",
  "integrity": "sha256-OYP9B9EPFBi1vs0dUqOhSbHmtP+ZSTsUv2/OjSzWK0w="
}
```

```html
<img
  src="https://example.com/image.jpg"
  integrity="sha256-OYP9B9EPFBi1vs0dUqOhSbHmtP+ZSTsUv2/OjSzWK0w="
/>
```

v0.7:

```json
{
  "type": "ExternalResourceTargetIntegrity",
  "cssSelector": "#hero-image",
  "integrity": "sha256-OYP9B9EPFBi1vs0dUqOhSbHmtP+ZSTsUv2/OjSzWK0w="
}
```

```html
<img src="https://example.com/image.jpg" id="hero-image" />
```

### Changed

- For Profile Annotation Issuer Registration PA, the exception rule exempting registrations issued by the OP Registry (trust anchor) from authorization checks has been removed. → [Documentation](https://docs.originator-profile.org/en/opb/pa-model/profile-annotation-issuer-registration/)
- If the authorization of a PA issuer cannot be verified, the system now issues an informational notification instead of a warning.
  This is because an inability to verify authorization does not necessarily mean the PA is invalid.
- The message displayed for sites lacking a Site Profile has been changed to "This site does not yet support OP."
- The link destination verification feature (which checks if the destination of an ad link belongs to the site operator declared in the content) now also verifies the OP signature of the destination site.
- Icons are now bundled with the extension instead of being fetched via the Iconify API.
- Even if a portion of the Website Profile contained within the Site Profile cannot be decoded, the system now proceeds to verify the remaining parts of the Website Profile.
  The error message indicates the location of the undecodable Website Profile (e.g., `sites[1]`).

### Deprecated

- `VisibleTextTargetIntegrity` has been deprecated.
  Rendering results based on `innerText` vary across browsers, making it unsuitable for integrity verification.
  A warning is now displayed when verifying Content Attestation that includes this Target Integrity.
  Please migrate to `TextTargetIntegrity` (or `HtmlTargetIntegrity`). → [Documentation](https://docs.originator-profile.org/en/opb/content-integrity-descriptor/text/)

v0.6:

```json
{
  "type": "VisibleTextTargetIntegrity",
  "cssSelector": "#main",
  "integrity": "sha256-GYC9PqfIw0qWahU6OlReQfuurCI5VLJplslVdF7M95U="
}
```

v0.7:

```json
{
  "type": "TextTargetIntegrity",
  "cssSelector": "#main",
  "integrity": "sha256-GtNUUolQVlwIkQU9JknWkwkhfdiVmHr/BOnLFFHC5jI="
}
```

The `integrity` value needs to be recalculated.

### Removed

- Removed the functionality to access the registry API using Basic authentication with credentials bundled at build time.
  Consequently, removed `webRequest` and `webRequestAuthProvider` from the permissions requested by the extension.

### Fixed

- Fixed an issue where the reason for the error was missing from the "unsupported screen" and detailed information for pages where content scripts cannot be injected (such as the Chrome Web Store).
- Fixed an issue where an incorrect organization name was displayed on the link verification warning screen and in the detailed information.
- Fixed an issue where the warning would reappear after a period of inactivity, even if the user had selected "Proceed anyway" on the link verification warning screen.
- Fixed a typo (`outilne`) in the overlay CSS.

## WordPress Plugin

### Added

- Added a setting to CA Manager to exclude articles matching specified URL patterns from automatic CA issuance.
  For example, if `/blog/**` is set, CAs will not be issued when articles under `/blog/` are published or updated.
  The setting applies to future publications or updates; existing CAs are neither deleted nor revoked.
- Added logging for cases where signing fails because the image integrity value cannot be retrieved.
- Added a notice in the admin interface indicating that `VisibleTextTargetIntegrity` is deprecated.
- Added a "Tools > Bulk CA Issuance" screen to issue CAs in bulk for published articles.
  You can filter targets by post type, publication date, and category, and choose to issue CAs for "Unissued Only" or "All Items."
  Processing proceeds article by article, supporting pause, resume, and cancel functions, as well as retries for failed articles.
  Exclusion settings based on URL patterns are also applied.
- Included `cssSelector` in the External Resource Target for images.
  The selector (e.g., `img.wp-image-123`) is derived from the `wp-image-{attachment ID}` class that WordPress assigns to the `<img>` element in image blocks.
  The `integrity` attribute continues to be added to `<img>` elements to ensure previously signed CAs remain verifiable.

### Changed

- Changed the default CA server hostname to `playground.originator-profile.org`.
- Explicitly stated in the README the policy that supported PHP versions must have active security support.

### Fixed

- Fixed an issue where the API authentication (OIDC) screen would result in a 404 error in WordPress 7.x when the permalink setting was set to "Plain."
  Changes to the OIDC redirect URL are scheduled to be addressed in the next release of the CA server.

## npm package

### Added

- Added a client library, [`@originator-profile/ca-client`](https://www.npmjs.com/package/@originator-profile/ca-client), for signing Content Attestations on the CA server.
  - `createCaClient`: Generates a client that requests the CA server to sign unsigned CAs (`sign`) or re-sign existing CASs (`reSign`).
  - `writeCasFile` / `readCasFile`: Reads and writes Content Attestation Set files.
  - `detectDrift`: Recalculates Target Integrity from the post-build HTML and detects discrepancies against the values recorded in the CAS.
- `@originator-profile/verify`: Added `verifyWebsite` (for sites) and `verifyDocuments` (for documents).
  This allows other applications to utilize the same verification processes used by OP Inspector.
- `@originator-profile/verify`: Added a serializable verification result type modeled after the VC Data Model 2.0 verification results.
  Errors are recorded as "Problem Details" objects—where the `type` field contains the URL from the [Error Reference](https://docs.originator-profile.org/en/error-reference/)—along with a `pointer` indicating the location.
  Warnings and informational messages are recorded in `warnings` and `info` fields, respectively.
- `@originator-profile/verify`: Made it possible to override the output destination for warnings and informational messages during verification using the `logger` option (accepting `{ warn, info }`; defaults to `console`).
- `@originator-profile/presentation` / `@originator-profile/verify`: Added the retrieval path (`source`) to the VC retrieval results and the OPS/CAS verification results.
  The retrieval path can be a registry, a Site Profile, or an HTML embedding.
- `@originator-profile/sign`: Updated the key arguments for `signJwtVc`, `signWsp`, `signCp`, and `signCa` to accept `CryptoKey` or `KeyObject` instances, as well as `JwtSigner` objects representing external signers.
  This enables signing in environments where private keys cannot be extracted, such as HSMs or cloud KMS.
- `@originator-profile/model`: Added a `cssSelector` property to the External Resource Target.
- `@originator-profile/model`: Made the `credentialSubject.id` field in `UnsignedContentAttestation` optional.
  If omitted, the CA server assigns the CA ID.

### Changed

- **Breaking Change** `@originator-profile/verify`: Consolidated the optional trailing arguments (`fetcher`, `validator`, `verifyOrigin`) for `verifyImageDigestSri`, `OpsVerifier`, and `SpVerifier` into an options object.

v0.6:

```ts
await verifyImageDigestSri(image, fetcher);

OpsVerifier(ops, keys, issuer, validator);

SpVerifier(sp, keys, issuer, origin, verifyOrigin, validator);
```

v0.7:

```ts
await verifyImageDigestSri(image, { fetcher });

OpsVerifier(ops, keys, issuer, { validator });

SpVerifier(sp, keys, issuer, origin, { verifyOrigin, validator });
```

- `@originator-profile/verify`: Updated `SpVerifier` to continue verification even if parts of the Website Profile cannot be decoded; it now returns the verification results for all parts within `SiteProfileInvalid`, preserving their original order.

### Deprecated

- `@originator-profile/model`: Deprecated `VisibleTextTargetIntegrity`.

### Removed

- **Breaking Change** `@originator-profile/opvc`: Removed `signByServer`.
  Please use `createCaClient` from `@originator-profile/ca-client` instead.
  Authentication has shifted from access tokens to OAuth client credentials (`ccspConfig`).
  `issuedAt` and `expiredAt` can no longer be specified; the resulting CA is valid for one year from the time of signing.

v0.6:

```ts
import { ContentAttestation } from "@originator-profile/opvc";

const jwt = await ContentAttestation.signByServer(uca, {
  endpoint: "https://example.com/ca",
  accessToken: process.env.CA_SERVER_ACCESS_TOKEN!,
});
```

v0.7:

```ts
import { createCaClient } from "@originator-profile/ca-client";

const client = createCaClient({
  endpoint: "https://example.com/ca",
  issuer: "dns:example.com",
  ccspConfig: process.env.CA_SERVER_CCSP_CONFIG!,
});
const jwt = await client.sign(uca);
```
